# 测试规范：测行为，不测数值

## 核心命题

**测试的唯一目的是在代码出错时失败。**

一个永远不会失败的测试不是测试，是装饰。AI 最省事的作弊方式是把覆盖率刷到 100%：

```python
assert result is not None
assert isinstance(result, dict)
```

这两行没有证明任何行为。它们只证明了"函数返回了东西"——而 bug 恰恰经常藏在"返回了错的东西"里。

> 一个 bug 就是一个行为没有被约束住。测试就是把行为钉死。

## 写测试之前先回答三问

1. 这条测试证明的是哪个**行为**？
2. 如果有人改坏这个行为，它会失败吗？
3. 失败信息能不能直接指出**哪里坏了**？

有一问答不上来，就说明这条测试还不该写——先想清楚行为。

## 什么算"行为"

行为 = 输入 → 可观察的结果：

- 返回值（内容与结构）
- 抛出的异常（类型与时机）
- 状态变化（存储、事件、文件、队列）
- 边界处的对外调用（网络、子进程）

断言要落在这四类上。**不要**落在：

- 对象是不是某个类型
- 字段是不是非空
- 私有属性等于某个值
- 内部函数被调了几次
- 实现细节（缓存命中、调用顺序）

## 坏测试 vs 好测试

坏：

```python
def test_create_idea() -> None:
    idea = create_idea("x")
    assert idea is not None
    assert isinstance(idea, Idea)
    assert idea.title == "x"
```

好：

```python
def test_creating_idea_persists_and_emits_event(fake_store: FakeStore) -> None:
    idea = create_idea("x")

    assert fake_store.get(idea.id) == idea
    assert fake_store.events[-1].type == "idea.created"
```

区别不在断言数量，而在**断言落在可观察的行为上**：持久化了、事件发了。第一条测试即使 `create_idea` 返回一个空壳对象也会通过。

## 边界与属性测试

手写 `0 / -1 / None / ""` 的排列组合是重复劳动，而且容易漏。能用属性测试就用：

- Python：Hypothesis
- TypeScript：fast-check

适合属性测试的：序列化往返、解析、排序、幂等、长度与单调性等不变量、状态机。

属性测试测的仍然是行为（"对任意输入，这个不变量成立"），不是"这个值等于多少"。

## 覆盖率的正确用法

- 覆盖率是**发现未测试区域的探针**，不是目标。
- **禁止为了提升覆盖率写测试。**
- 真正衡量测试是否有效的是**变异测试**：把实现改坏，看测试会不会失败。Python 用 mutmut，TS 用 Stryker（P1 再引入）。

## 本项目里的测试层次

| 层 | 证明什么 | 位置 |
|---|---|---|
| 内核行为 | 加持 / 卸载 / 引用、消息转发 | 与 `app/core/` 同包 |
| 插件行为 | 装上能用、卸了干净、服务取得到 | 与插件同包 |
| 协议 | 两种语言的消息形状一致 | 待定 |
| 渲染引擎 | 节点树 → 界面、事件回传 | `app/ui-engine/` |

## 写法约定

- 名字描述行为：`test_creating_idea_emits_event`，不要 `test_1` / `test_works`。
- 一个测试一个行为；多个断言服务于同一行为可以，不相关断言不要堆。
- arrange / act / assert 三段清楚，中间不藏逻辑。
- 只在边界打桩（网络、时间、文件、随机）；不 mock 被测对象本身。
- 时间、ID、随机数从注入的钟取；测试里禁止 `sleep`。
- 断言失败信息要能定位问题，必要时加自定义消息。

## 评审清单

- [ ] 这个测试失败时，能指出哪个行为坏了？
- [ ] 断言是行为，不是类型 / 非空 / 实现细节？
- [ ] 换掉实现、行为不变，测试是否仍然成立？
- [ ] 边界是否覆盖，而不是只有 happy path？
- [ ] 有没有为了覆盖率硬凑的测试？
- [ ] 是否可重复（无真实时间、网络、随机依赖）？

## 一句话标准

**如果一个测试在"实现变了但行为没变"时会失败，那它测的是实现，不是行为。**

## 机器能拦的部分

还没有自动化护栏。先靠三问和评审；等代码落地再补。
