# 路线图

> 只写**方向、阶段、退出条件与止损条件**。完成记录在 [changelog](changelog.md)，未完成工作在 [TODO](todo.md)。
> 时间尺度：**现期 2 周 / 近期 2 月 / 长期 3 月（累计第 6 个月）/ 展望 1 年+**。基线 2026-11-20。
> 现状与证据见 [项目现状](planning/state-of-project.md)；目标架构见 [V1 树](planning/v1-tree.md)；怎么定方向见 [决策机制](planning/decision-process.md)。

## 0. 定论

> **引擎先完善，产品闭环随后。**
> 理由只有一条：引擎半途而废，业务迁移成本会翻倍；现在产品只有一页，是换地基最便宜的时候。

三句话：

1. **引擎核心必须做完。** 静态结构、ops 协议、默认主路径与旧路径删除已落；剩余核心 = Python 脏节点产线 + data / collection 产线 + 类型检查 + 复杂度护栏。能力补齐（布局、层/焦点、组件广度、i18n、主题动效、交互）按 [引擎能力补齐](planning/engine-capabilities.md) 的 M2–M6 **轮子优先**补；非核心（规则执行、远程来源）随业务与维护补。**可篡改权 / 引擎级权限与审计不做**——页面级差异用“按权限发不同结构的 tree”，归插件/宿主。
2. **产品不是消失，是后置。** 长期做 Idea 闭环 + Project 闭环；需求（requirements）最后。
3. **每条轨道有到期日。** 第二实现、实验、迁移，都要有结论，不许变成默认背景。

### 引擎核心 / 非核心

| 类别     | 内容                                                         | 处理               |
| -------- | ------------------------------------------------------------ | ------------------ |
| 核心     | 脏节点产线、data / collection 产线、类型检查、复杂度护栏     | 近期必须做完       |
| 能力补齐 | 布局、层/焦点、组件广度、i18n、主题动效、交互、工程护栏      | 按 M2–M6 轮子优先  |
| 非核心   | 规则执行、远程来源、订阅 / 媒体登记、集合嵌套                | 业务推进时顺带维护 |
| 不做     | 可篡改权 / 引擎级权限、审计；自研布局/动画/拖拽/虚拟列表引擎 | 不排期             |

## 1. 现期：引擎收口第一段（2026-11-20 → 2026-12-04）

**目标**：把“协议已经最小、计算仍全量”的落差补上，让默认入口的链路真正 O(k)。

- Python 脏节点产线：事件后只算被改的节点，不再整页重建再差分。
- data / collection 产线起步：Python 发 `data` op；collection 实例化 / bind / changes。
- 复杂度护栏：事件 → DOM 的工作量不随总节点数增长，进 CI。
- 类型检查后半：per-kind settings schema、on / bind 引用、warning 码。

**退出条件**：

- ideas 一页的捕获 / 搜索 / 详情走 O(k) 产线，事件不重建整页。
- data op 有跨语言 fixture 与产线；collection 至少一页能用。
- 斜率测试挡住“改一个小节点、全树重算”。
- 全量门禁绿。

**止损**：脏节点产线一周内定不下形状，就先只做 data / collection 产线与护栏，
把“全页重建”记为已知债，不半接、不双产线。

## 2. 近期：引擎收口与 0.2（2026-12 → 2027-02）

**目标**：核心能力收完，发布 0.2。

- 默认入口唯一（已落）：V1 树主会话 + `ui.changed`；全量只作首帧 / 重连 / 兜底。
- 数据驱动界面：data / collection / bind 产线可用，至少一页真实使用。
- 能力补齐 M2–M6（轮子优先，见 [引擎能力补齐](planning/engine-capabilities.md)）：
  布局 vocabulary、层/焦点、Zag 组件广度、i18n 完整化、主题/动效、拖拽/快捷键、工程护栏。
- 0.2 发布：冻结 schema + 迁移 runner + 一条真实迁移 + 安装包 + release notes。

**退出条件**：默认入口只有 V1；事件 → DOM 不随总节点数增长；数据驱动界面可用；
0.2 有 tag、安装包与迁移；全量门禁绿。

**止损**：某个能力迁不动，记 ADR 并保留现状缺口，不阻塞其余。

## 3. 长期：Idea 闭环 + Project 闭环（2027-02 → 2027-05）

**目标**：两个闭环形成基本架构。需求（requirements）后置。

**Idea 闭环**：

- 记下：文字 / 语音 / 视频，录了即存。
- 整理：搜索、标签、置顶、归档。
- 关联：灵感 ↔ 灵感、灵感 ↔ 项目。
- 用上：转写进搜索；从项目反查来源。

**Project 闭环**：

- 建项目 → 关联灵感（需求后置）→ 状态推进 → 归档 / 复盘。
- 从项目能看见它的灵感来源；从灵感能看见它去了哪个项目。

**退出条件**：一条灵感从记下到被项目用上，不离开 Omora；一个项目从 0 到归档，来源可追溯；重启不丢；0.2 已发布，升级不丢数据。

**止损**：闭环需要引擎新能力时，先记 ADR，不在业务里绕。

## 4. 展望：长期维护与领域插件（2027-05 → 1 年+）

引擎稳定后，长期是两件事：维护，和在部分领域插件里试新东西。

候选尝试（不承诺，按真实痛点决定）：

- **AI 开发**：提升 AI 辅助开发的上限，不只是补全。
- **架构设计**：把架构设计、组织结构的知识做成能力。
- **邮件聚合**：多账号统一收件箱，主邮箱回复。

邮件这条值得单独说：很多开发者手上两三个、三四个邮箱，通知分散、信息难统合；现有软件要么收费，要么大公司不做这种小场景；“收件箱聚合”很多企业软件也不做。用户不关心是哪个账号发的，关心邮件本身，由主邮箱回过去就行。这是典型的“小场景、真痛点、适合插件”。

判断标准：真实痛点、能做成插件、不破坏本地优先。三条都满足才做；不满足就留在文档里。

## 5. 横切规则

- 引擎核心由**真实页面**验收，不由能力清单验收。
- 第二实现 / 实验 / 迁移：三个问题 + 一个结论文档 + 一个到期日。
- 默认入口唯一。
- 每两周复盘：闭环能否走通、文档漂移、队列健康。
- 文档单一状态源。

细则见 [决策机制](planning/decision-process.md)。

## 6. 非目标

- 多人协作 / 房间 / 实时协同。
- 云同步。
- 移动原生 App（先做浏览器端）。
- 生态开放 / 插件市场。
- React 式函数组件、hooks、JSX、隐式重跑。
- 插件版本范围解析。
- 在没有页面需要前扩组件词表。
- 可篡改权 / 引擎级权限、审计：页面差异归插件树结构，引擎不判定。
- 自研布局、动画、拖拽、虚拟列表引擎：能买标准件就买。
- `yoga-layout` 这类 WASM 布局引擎：丢 CSS 与无障碍，不引。
- 需求（requirements）不是当前重点。
