# 决策记录（ADR）

> 这里只放**跨模块、会改变项目形状**的决定。任务、状态、进度不在这里：
> 方向见 [路线图](../roadmap.md)，未完成见 [TODO](../todo.md)，完成见 [changelog](../changelog.md)，
> 具体交付见 GitHub issue / PR。

## 1. 它回答什么

一条 ADR 只回答一个问题：**为什么当时这么定，代价是什么。**

它不记录"做了什么"（那是 changelog 和 PR），也不记录"接下来做什么"（那是 roadmap / TODO）。
它的读者是半年后的人：看到一段反直觉的代码，先来这里找当时的约束。

## 2. 什么时候写

命中任意一条就写：

1. 改**契约**：schema、协议帧、树形状、身份模型；
2. 改**默认入口**或加第二条运行时；
3. 加**第二实现**（原型、实验、扫雷）——必须带到期日；
4. 改**目录结构或依赖方向**；
5. **冻结 / 解冻 / 删除**一条轨道。

不写：一次实现细节、可回滚的小实验、纯样式 / 文案 / 测试。
判定标准：**这个决定会不会让下一个人读错项目？** 会，就写。

## 3. 放哪、怎么编号

- 位置：`docs/decisions/`（与 `docs/engine/` 平级——ADR 是跨模块的，不属于某个子系统）。
- 文件名：`NNNN-短名.md`，四位递增，**编号不复用**；被取代的保留原文件并改状态。
- 已有：0001–0005（见 [目录](.)）。
- 引擎内部的设计记录、历史归档仍在 `docs/engine/`，但**跨模块的决定必须来这里**。

## 4. 状态四档

| 状态   | 意思                                |
| ------ | ----------------------------------- |
| 提议   | 已写、还没拍板；代码不应依赖它      |
| 已接受 | 作者拍板，代码按它来                |
| 已废弃 | 不再适用，但保留原文与原因          |
| 被取代 | 有更新的 ADR 接替；两条都要链到对方 |

**被否掉的方案不删**：写清为什么否，否则同一个方案会被反复提。

## 5. 结构

```md
# ADR-000N：一句话结论

- **状态**：已接受（YYYY-MM-DD）
- **决策者**：项目作者 + Lead
- **相关**：链接到 roadmap / 设计文档 / 其它 ADR

## 背景

## 决定

## 后果（得到 / 要自己负责 / 风险与缓解）

## 被否掉的方案

## 到期日或触发条件（实验 / 第二实现必填）
```

## 6. 谁拍板

- 项目作者拍板；Lead 起草、补证据、落成文档。
- Agent 不自行"接受"一条 ADR，也不替作者做产品决定。
- 讨论留在 PR 与会话里，结论才进 ADR；ADR 里不写聊天记录。

## 7. 与其它文档的分工

| 问题               | 只看                         |
| ------------------ | ---------------------------- |
| 现在按什么架构做   | 由"已接受"的 ADR 决定        |
| 方向与阶段         | [路线图](../roadmap.md)      |
| 未完成             | [TODO](../todo.md)           |
| 已完成             | [changelog](../changelog.md) |
| 某次改动的来龙去脉 | GitHub PR                    |
