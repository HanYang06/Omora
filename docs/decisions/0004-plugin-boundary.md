# ADR-0004：插件之间的边界与数据可见性

> 状态：已采纳 · 日期：2026-11-08 · 影响 C2

## 背景

P1 要做「灵感分诊到项目」。这逼出一个必须现在回答的问题：**插件 A 怎么用插件 B 的数据？**

三个诱人的做法，都错：

1. 让内核提供一个共享数据表 —— 内核立刻长出领域模型，边界破了；
2. 允许插件互相 import —— 变成一个大程序，卸载与替换全部失效；
3. 让插件直接读别人的状态切片 —— 能力隔离作废，一个插件能改另一个插件的账。

## 决定

**插件之间只有两条通道：事件与服务。没有任何共享数据。**

| 通道 | 方向 | 语义 |
|---|---|---|
| 事件 | 广播，异步，单向 | 「已经发生了什么」。发布者不知道谁在听 |
| 服务 | 点对点，请求 / 响应 | 「帮我做一件事」。提供方登记，消费方按名字调用 |

具体规则：

- **状态按插件分片**，插件只能读写自己那一片；`state[plugin_id]` 是它的全部可见世界。
- **渲染时只拿自己的切片**。视图函数是同步纯函数，不做 IO，不等待别的插件。
- **跨插件数据要用事件同步过来**。需要展示对方数据时，订阅对方事件，把需要的那一点缓存进自己的切片。
- **服务调用可以失败**。提供方没装或已卸载，消费方拿到 `E_UNAVAILABLE`，必须自己决定降级方式。

## 后果

好处：

- 卸载任意插件，剩下的插件行为不变，只是少了那个插件的功能与被缓存的数据；
- 同一个能力可以有多个提供方（未来做优先级与回退），消费方无感；
- 核心不实现任何服务，`git` / `ai` / `search` 全部由插件提供，与文档一致。

代价：

- **渲染路径上拿不到实时跨插件数据**。要展示就得订阅并缓存，缓存的时效由事件保证，不由查询保证。
- 事件类型是插件自定义的，没有 schema 约束；跨插件事件约定只能靠文档与测试。
- 服务调用是同步等待，一个慢服务会拖慢命令；后续需要超时与取消（P2）。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 内核提供关系表 / 共享实体 | 核心立刻长出领域模型，违反 ADR-0002 |
| 插件直接读别人切片 | 能力隔离作废；一个插件的 bug 会污染全局 |
| 异步视图（渲染时 await） | 渲染变成副作用，前端需要处理悬挂状态，复杂度换来的只是少写一条订阅 |
| 共享内存对象 | 跨语言与跨进程层级无法成立，与 C2 语言中立冲突 |
