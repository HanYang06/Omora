# 方向怎么定

> 状态：**已定**，随 [路线图](../roadmap.md) 一起生效。
> 解决的问题：每次开工都要先重新了解一遍项目；方向只存在于口头和某一份过期文档里。

## 0. 为什么要有这个

决策债比技术债贵。两套树并行、两份相反的"下一步"，都不是技术判断错了，而是**没有约定"谁在什么时候、按什么标准定"**。

这份文件只写机制，不写方向。方向在路线图，队列在 TODO。

## 1. 什么必须写 ADR

只有五类，其他（功能、样式、文案、测试）不需要：

1. **改默认入口**：第二条运行时、换引擎、换主会话路径。
2. **改契约**：schema、协议帧、树形状、身份模型。
3. **加第二实现**：扫雷、原型、实验分支、并行轨道。
4. **改目录结构或依赖方向**。
5. **冻结 / 解冻 / 删除一条轨道**。

判定标准很简单：**这个决定会不会让下一个人读错项目？** 会，就写。

## 2. ADR 放哪、怎么写

- 位置：`docs/engine/decisions/`（已有 0001–0004）。
- 文件名：`NNNN-短名.md`，编号递增。
- 一条 ADR 只回答一个决定；实现细节留给设计文档。
- 模板：标题 / 状态 / 决策者 / 相关 / 背景 / 决定 / 后果（得到、要自己负责、风险与缓解）/ 被否掉的方案 / 验收。
- 状态四档：提议、已接受、已废弃、被取代。**被否掉的方案不删**，写清为什么否。

## 3. 阶段门禁

每个阶段必须同时写三样，缺一样就不算阶段：

| 项       | 要求                                                 |
| -------- | ---------------------------------------------------- |
| 退出条件 | **用户可见**，不是"测试绿""CI 绿"                    |
| 止损条件 | 到点没成，砍哪一块、降级成什么                       |
| 复盘动作 | 继续 / 调整 / 止损，三选一，写进路线图对应阶段的记录 |

**到点必须有一个动作。** 没有动作的阶段会变成默认背景，永远不结束。

## 4. 三条硬规则

1. **默认入口唯一。** 任何时刻只有一条默认运行路径。第二套可以存在，但不能同时是"默认"。
2. **第二实现有到期日。** 三个问题 + 一个结论文档 + 一个日期，缺一个就不许合并。
3. **地基分核心与扫雷。** 核心由架构缺陷推导，必须有 ADR，必须做完，由真实页面验收；扫雷由未知推导，必须有到期日。两者都不以「以后可能」为理由。

## 5. 复盘节奏

每两周一次，15 分钟，只看三个数：

| 数              | 从哪来                                      | 看什么                 |
| --------------- | ------------------------------------------- | ---------------------- |
| 真实页面 / 闭环 | 阶段验收脚本                                | 能不能走通；卡在哪一步 |
| 文档漂移        | [现状](state-of-project.md) §5 的不一致条数 | 只增不减就是没在维护   |
| 队列健康        | [TODO](../todo.md)                          | Blocked 数、过期项数   |

输出只有一句话 + 一个动作，不写成会议纪要。

## 6. 文档单一状态源

| 问题               | 只看                              |
| ------------------ | --------------------------------- |
| 方向、阶段、门禁   | [路线图](../roadmap.md)           |
| 现在有什么、哪坏了 | [现状](state-of-project.md)       |
| 未完成的工作       | [TODO](../todo.md)                |
| 已完成             | [changelog](../changelog.md)      |
| 为什么这么定       | [decisions](../engine/decisions/) |

其他文档（README、ARCHITECTURE、engine 系列）只链接，不复述阶段状态。

## 7. 变更流程

- **谁提**：任何人。
- **谁定**：项目 owner。
- **怎么记**：先写 ADR，再改路线图，最后改代码/文档。
- **怎么否**：ADR 里写"否掉了什么、为什么"，记录保留。
- **紧急情况**：可以先做，24 小时内补 ADR；不补就回滚。
