# P0：垂直切片

> 目标：证明「一个 Python 插件能通过协议在界面上画出一块面板，并且数据来自内核」。这一条跑通，架构就成立；跑不通，趁早改。

## 状态：已完成（M0.0–M0.6）

证据：

- `uv run python scripts/check.py` → 23 个阶段全绿；
- `uv run pytest -q` → 212 个测试；
- `uv run python scripts/accept_p0.py` → 对着一个真实运行的内核跑通：快照带 state 与 ui、ideas 插件贡献出现在 sidebar、命令落库后事件回推并更新切片、重连能按 revision 追赶；
- 验收 4（禁用插件无残留）由 `kernel/tests/test_host_isolation.py` 与 `test_host.py` 证明；
- 验收 6（未知节点降级为占位符）由 `web/tests/renderer.test.tsx` 证明。

放宽项见 [工程纪律](../engineering/discipline.md) 的「P0 明确放宽的项」。

## 1. 范围

**做：**

- 单工作区、单用户、无鉴权
- 内核：服务容器、SQLite 存储、事件日志、C1 WebSocket
- 渲染器：六个节点、两个槽位、增量更新
- 插件宿主：发现 / 激活 / 卸载 / 贡献 UI
- 官方插件：ideas（灵感增删改查）

**不做：**

- 桌面壳、服务器部署、多用户
- 同步、CRDT、Git
- 插件市场、签名、沙箱层级
- 移动端、主题系统、快捷键系统

## 3. 模块职责

| 路径 | 职责 | 不做什么 |
|---|---|---|
| sdk/src/omora_sdk/ | 插件对外类型与能力声明 | 不含任何领域概念 |
| kernel/src/omora_kernel/context.py | Context、provide / inject、scope、lifecycle | 不碰存储与协议细节 |
| services.py | 服务注册表与依赖解析 | 不做业务 |
| store.py | SQLite 事务、迁移、备份 | 不做同步 |
| eventlog.py | 追加事件、revision、追赶 | 不做投影 |
| transport/ws.py | 帧、连接、背压 | 不做业务 |
| contract/c1.py | C1 方法实现 | 不暴露内部对象 |
| contract/c2.py | C2 方法与清单校验 | 不做权限判断（交给能力代理） |
| ui/validate.py | C3 节点校验与降级 | 不做渲染 |
| plugins/ideas/ | 官方灵感插件（独立包） | 只 import omora_sdk，不 import 内核内部 |
| web/src/rpc/c1.ts | C1 客户端、重连、revision 追赶 | 不做业务 |
| web/src/store/projection.ts | 投影合并 | 不做 UI |
| web/src/renderer/index.tsx | schema → 视图 | 不做业务 |
| web/src/renderer/widgets/ | 六个原语控件 | 不做领域组件 |
| web/src/shell/ | 槽位布局 | 不做插件管理 |
| scripts/check.py | 统一门禁 | 不写业务逻辑 |

**硬规则：官方插件只能依赖对外 SDK，不能 import 内核内部模块。** 这是无后门原则的工程落地。

| 里程碑 | 内容 | 验收 |

| M0.5 | 插件宿主 + ideas 插件：清单发现、激活、贡献、卸载 | 插件能注册命令并往 sidebar 填内容 |
| M0.6 | 验收与韧性：重连、追赶、热禁用 | 六条验收全过 |

## 5. 验收

1. 启动内核与前端，UI 显示来自内核快照的灵感列表；
2. 输入标题回车 → C1 命令 → 内核落库 → 事件 → UI 追加；
3. ideas 官方插件通过 C2 注册命令、通过 C3 往 sidebar 填内容；
4. 禁用插件 → 它注册的命令与 UI 贡献全部消失，无残留；
5. 内核重启 → 前端自动重连并补齐 revision 之后的事件；
6. 渲染器遇到未知节点类型 → 显示占位符，不崩溃。

## 6. 技术选型

| 位置 | 选择 |
|---|---|
| Python | 3.14（uv 固定，见 `.python-version`） |
| 内核并发 | asyncio，单事件循环 |
| 存储 | sqlite3（标准库），WAL 模式 |
| 校验 | pydantic v2 |
| 传输 | websockets |
| 前端 | TypeScript strict + tsc（P0-0）；Vite + React 于 P0-1 引入 |
| 门禁 | `uv run python scripts/check.py` |
| 前端状态 | 手写投影 + 订阅，不引状态库 |

## 7. 风险

| 风险 | 后果 | 对策 |
|---|---|---|
| C1 被设计成 CRUD 而不是命令 / 事件 | 后面必定返工 | 先写事件路径，再写查询路径 |
| 渲染器过早引入框架抽象 | 被框架锁死 | 渲染器只认 type → 组件映射表 |
| 插件宿主与内核耦合 | 变成假插件系统 | 官方插件走 SDK，review 时检查 import |
| 前端投影与内核不一致 | 幽灵状态 | revision + 断线重放 + 全量快照兜底 |
