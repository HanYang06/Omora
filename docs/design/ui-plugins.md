# UI 插件体系（键、贡献、组合）

> 这份文档定的是"插件怎么写界面、引擎怎么把它拼起来"。它替换了原来"一页 = 一棵树"的模型。
> 定下来的才写，没定的标"未定"。

## 0. 一句话

**界面 = 若干份贡献，挂在若干把键上，由引擎组合成一棵树。**
引擎只做执行（渲染、组合、回传事件），不做判断（谁该出现、缺了什么算不算错）。

验收标准只有一条：

> **写一个新插件，`app/ui-engine/` 一行都不用动。**

## 1. 键

键是全限定名，第一段是声明者（插件 id），后面是它自己的路径：

    ideas.home.after_capture
    om.window.page
    audio.settings.panel

四条规矩：

1. **键全局唯一。** 声明者前缀保证不撞；两个插件声明同一个键，构建期报错。
2. **有键 = 可介入；没键 = 私有。** 这是"固定组件 / 可替换组件"的唯一判据，不需要维护清单。
3. **键是公开契约。** 发布之后不改名；改名等于破坏性变更（系统插件一起发版，生态插件按文档走）。
4. **键由构建期生成。** 作者不手写字符串，写生成出来的对象/常量；写错是类型错误，不是运行期静默。

## 2. 结构：窗口、页面、贡献

| 概念     | 是什么                               | 谁声明             |
| -------- | ------------------------------------ | ------------------ |
| **窗口** | 母 UI 的根，声明有哪些区域           | 引擎（默认母页面） |
| **页面** | 一个可导航的根，挂在窗口的某个区域上 | 页面 owner 插件    |
| **贡献** | 一份树 + 一个落点键 + 一个顺序       | 任意插件           |

线上形状（`ui.render` / `ui.snapshot` 的视图部分）：

```json
{
  "pages": [{ "name": "ideas", "label": "灵感", "icon": "ideas" }],
  "page": "ideas",
  "version": 12,
  "content": { "type": "split", "props": {}, "children": [] },
  "contributions": [
    {
      "owner": "projects",
      "target": "ideas.home.after_capture",
      "op": "append",
      "order": 20,
      "seq": 1,
      "tree": { "type": "row", "props": {}, "children": [] }
    }
  ]
}
```

- `pages` / `page`：导航与当前页（沿用 v1，含义不变）。
- `content` 是页面主人自己那棵树的简写；引擎组合前会给它的根打上 `om.window.page`，所以整页也能被挂接或替换。
  等贡献层稳定，它会并进 `contributions`；现在两种都在线上，引擎先摆 `content` 再挂 `contributions`。
- `version`：当前页的组合结果版本，单调递增。
- `contributions`：**这一页**的贡献集合。换页 = 换整组贡献，不是打补丁。
- 窗口区域先定两个：`om.window.nav`（图标栏）与 `om.window.page`（主区）。再加区域要改引擎，这是有意的——区域是平台结构。

## 3. 挂接动作

只有四个，语义对齐 DOM：

| op        | 落点         | 意思               |
| --------- | ------------ | ------------------ |
| `replace` | 键所在的节点 | 整个换掉           |
| `after`   | 键所在的节点 | 挂在它后面，同级   |
| `before`  | 键所在的节点 | 挂在它前面，同级   |
| `append`  | 键所在的节点 | 放进它的子节点末尾 |

**顺序是全序：`(order, owner, 声明序号)`。**

- `order` 默认 0，整数，建议留空档（10 / 20 / 30）。
- 同 order 比 owner（字典序），所以顺序**只取决于装了哪些插件**，不取决于安装历史、不取决于到达顺序。
- 同一个插件往同一个键交多份，按声明序号；幂等的身份是 `(owner, target, op, 声明序号)`。

**`replace` 之后键还在。** 替换树的根由引擎打上目标键：覆盖因此可以叠加，替换后的节点也还能被别的插件继续挂。
替换树自己声明了别的键 → 记日志并强制改成目标键。

**覆盖（同一个键上的 `replace`）走另一条轴：后来者优先。**

- 系统插件是一致者：按代码里的固定顺序，谁也不是后来者。
- 运行后插件按安装时间排在后面，天然覆盖前面的。
- 覆盖链要能被查（`key → 谁改过`），并且检测成环（A 覆盖 B、B 覆盖 A → 后一次丢弃并记日志）。

## 4. 归属与生命周期

- **归属打在贡献上，不逐节点盖戳。** 一份贡献一个 owner，里面所有节点都归它。
- **handler id = `owner:serial:序号`**。事件回来时按 owner 找到那张 handler 表，所以一页可以有多个 owner，各管各的回调。
- **卸载级联**：插件卸了，它交的贡献全撤；它声明的键消失，挂在那些键上的别人的贡献也一起撤（各记一条日志）。
- 插件登记的一切都挂 `ctx.effect`，卸载逆序撤销（沿用内核那套）。

## 5. Python 写法

三层分开：**声明是对象，数据是方法，行为是回调。**

```python
class Ideas:
def apply(self, ctx):
self.collection = ctx.resolve("store").collection("ideas", ...)
self.page = ctx.resolve("ui").page(self.ctx, "ideas", label="灵感", icon="ideas")
self.page.set(
Split(
Rail("全部灵感", *self.rail_items()),
Column(
Search(placeholder="搜索灵感…", on_submit=self.search),
Slot(key="ideas.home.after_capture"),
Panel(content=self.feed()),
),
)
)

    def rail_items(self) -> list[Node]: ...
    def feed(self) -> list[Node]: ...

    def archive(self, event: ArchiveEvent) -> None:
        self.collection.update(event.id, archived=True)
        self.page.refresh(self.feed)

```

规矩：

1. **声明是对象。** 构造出来就是死的结构，没有回调、不看数据。**代码的形状 = 界面的形状**：一个表达式一棵树，缩进就是层级。
2. **数据是方法。** 一个方法只回答一个位置的内容，能单独测。
3. **结构变化 `set`，数据变化 `refresh`。** 前者换骨架（换模式、换页），后者只重算一个位置。
   `ui.page(...)` 返回页面对象：`set()` 交树、`refresh()` 重交一次；`projects` / `requirements` 已按这个写法迁完。
4. **`update()` 只标脏。** 节点改了就标脏，序列化与补丁由 runtime 做。
5. **构造统一**：第一个位置参数是内容（文字 / 标题），children 用 `*children` 放最后，其余全关键字。
   `Item` 已经改成 `Item(title, *actions, meta="")`；其余节点照这一条继续收。
6. **事件载荷是类型**，不是 `dict[str, Any]`；字段写错类型检查就红。
7. **只允许条目模板抽函数**（`item(record)`），因为它出现的地方本来就是列表；不许把整块页面抽走。
8. **不用 `with` 语法**：拿不到引用，`update()` / `refresh()` 就没了。

## 6. 引擎：组合器

**组合器是纯函数。**

    compose(window, contributions) -> tree, index

1. **校验**：键存在、不成环、同一 `(owner, key, op)` 不重复。
2. **定序**：按 `(order, owner, 声明序号)` 排。
3. **应用**：反复扫到不动——先应用落点已存在的贡献，再扫剩下的，直到没有进展；剩下的是死键，记日志丢弃。
4. **建索引**：`key → 节点位置`，供替换、卸载、调试用。
5. **不可变**：产出新树，改动路径复制、其余子树共享引用（memo 与补丁都靠它）。

**故障与对应规矩：**

| 故障                           | 规矩                                     |
| ------------------------------ | ---------------------------------------- |
| 键不存在                       | 丢弃 + 日志，不抛                        |
| 挂成环（贡献目标在自己子树里） | 拒绝该贡献，记日志                       |
| 提供键的节点卸载               | 级联撤掉挂在它上面的贡献                 |
| 同一份贡献重复到达             | 幂等：按 `(owner, key, op)` 替换，不追加 |
| 顺序相同                       | 全序兜底，绝不靠到达顺序                 |
| 一份贡献坏了                   | 只有它那一格降级成占位，壳和其他贡献照常 |

**增量**：只重组合脏的那份贡献，产出的新树与旧树 diff → 补丁；全量永远兜底。

**四条性质必须测**：幂等、增量结果 == 全量结果、失败隔离、顺序无关。

## 7. 引擎：订阅、错误、卸载

- **订阅声明化**：页面 / 快照里声明它需要哪些 topic（`ui.topics(ctx, ...)` 写进快照的 `topics`），客户端按声明补订 / 退订；引擎不写死插件 topic 名。
  组件自己订自己那一格（节点的 `stream` 属性）还没做。
- **错误边界**：每个节点一层；一个组件抛异常只降级成占位。
- **卸载账本**：引擎侧登记所有登记物（组件、订阅、监听），卸载逆序撤销。

## 8. 边界：引擎只做执行，不做判断

| 该归引擎                                   | 该归插件                         |
| ------------------------------------------ | -------------------------------- |
| 枚举设备、报原始事实（设备种类、权限状态） | "有没有麦克风、要不要出捕捉块"   |
| 渲染、组合、事件原样回传                   | 事件怎么处理、数据怎么来         |
| 平台原语（设备清单、媒体源显示、图形数据） | 这个图标长什么样、这段文案用什么 |

具体：

- **硬件**：引擎只报事实；manager 不再拿硬件当安装条件（`[tool.omora] capabilities` 降级成"声明需要什么"，只给设置页看）；audio / video 插件自己判断出不出捕捉节点。
- **图标**：节点自带图形数据，引擎不维护名字表。
- **样式**：只走语义令牌（面 / 间距 / 圆角 / 字级），插件不传 CSS。

判据：**引擎里出现的名字，是平台的名字，不是产品的名字。**

## 9. 静态骨架

- **编什么**：结构——窗口、区域、槽位位置、组件层级、顺序。以及各系统插件贡献组合出来的骨架。
- **不编什么**：由数据决定的形状（条数、有无媒体、空态切换）。这些走补丁。
- **产物**：`app/ui-engine/src/generated/static-tree.ts`——`STATIC_SNAPSHOTS`（每页一份）+ `STATIC_ORDER` + `STATIC_HASH`，import 即用。
- **脚本**：`scripts/static_ui.py` 用一个空 store 跑一遍系统插件、把每页画出来，**摘掉所有回调**（骨架里的按钮因此是禁用的）再写成模块；组合在客户端启动时做，构建期不重复跑 TS。
- **启动**：先画骨架（不等后端）→ 连上后端 → 第一份真快照替换它；导航对不上说明产物是另一版，记一条 `static.stale`。
- **确定性检查**：CI 跑 `static_ui.py --check`，产物与当前源码不一致就失败。跨数据 fixture 的"结构不依赖数据"检查还没做（当前页面结构仍由数据分支决定）。
- 生态插件不参与编译，永远是后到的增量。

## 10. 组件与组合能力

- **基础组件要够**：布局（顶栏 / 三栏 / 网格 / 堆叠 / 分隔 / 滚动）、表单（开关 / 复选 / 单选 / 下拉 / 多行 / 数字 / 表单行 / 按钮组）、反馈（弹层 / 确认 / 菜单 / 悬停 / 提示条 / 进度 / 加载 / 行内错误）、数据（表格 / 分组标题 / 字段行 / 时间线）、导航（标签页 / 折叠 / 面包屑）、媒体（图片 / 附件 / 文件选择 / 缩略图）。
- **组合能力四样**：尺寸规则（280 / 吃剩下 / 最小宽度）、变体（inset / paper、primary / ghost、title / muted）、局部状态（开合切换不回 Python）、组件内插槽（toolbar / content、header / footer）。
- **领域组件搬出去**：capture 这类回到 audio / video 插件自己的半边；引擎只留通用原语。

## 11. 插件形态

- **清单与语言无关**：插件 = 一份清单 + 若干语言的半边。系统插件用 `pyproject` 的 `[tool.omora]`；纯 UI 插件用 `plugin.json`（`id` / `version` / `ui` / `conditions`）。一个插件只有一份清单。
- **纯 TS 插件合法**：只有 UI 半边，数据向 Python 服务要；server 形态没有它。
- **TS 半边加载**（未定实现，门槛列出）：http 上的 ESM、React 单例、CSS 纪律、卸载、错误隔离、按软件主版本对齐。

## 12. 工具链

- `scripts/keys.py` 扫源码里的字面量（`Slot(key=...)` 声明、`contribute(..., target)` 使用），不跑插件。
- 产物三份（都是生成的，别手改）：`app/sdk/omora/sdk/keys.py`、`app/ui-engine/src/generated/keys.ts`、`keys.json`。
- CI：`uv run python scripts/keys.py --check` 校验产物最新；重复声明、格式不对、常量撞名都会失败。
- 编辑器：先要 VS Code 扩展（跳声明处、悬浮说明、谁在用），LSP 等要支持第二个编辑器时再说。
