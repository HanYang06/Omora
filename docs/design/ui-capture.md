# 捕捉工作区（就地展开 + 录了即存 + 两种录法）

这份文档固定「首页三个大按钮点下去之后发生什么」。它已经换过两版：

1. 整页捕捉（`capture_text` / `capture_audio` / `capture_video`）—— 页面没有自己的版式，
   三种媒体各长各的样；
2. 就地工作区 + 录了即存 —— 位置和保存时机对了，但录法只有一种、没有波形、不让你起名。

这一版补的是后两样：**录法**（点 vs 按住）和**事后**（波形、命名、暂停）。

## 1. 决定

- **入口就地。** 点 `Tile` 不换页，把捕捉区那一块换成工作区。索引栏与列表面板不动。
- **进工作区 ≠ 开始录。** 点 `Tile` 只是把工作区摆出来；开录要另一下。
- **录了即存。** 停止录制就是落库：没有「保存」按钮，不问「要保存吗」。
  灵感最容易掉，宁可多存一条，也不能少存一段。
- **命名在保存之后。** 先落库，再给一次起名的机会；不填就用时间轴默认名。
- **两种录法**：点一下＝长录（可以暂停），按住空格＝对讲（松手即停）。
- **音频走 HTTP 媒体通道**，不再塞进事件帧 —— 不限时长的录音按 base64 装不下。

## 2. 结构

首页主区顺序不变：搜索区 → 捕捉区 → 列表面板（区间 24）。捕捉区有三种形态：

| 形态 | 内容 |
|---|---|
| tiles | 三个块：录音 / 视频 / 文字（按插件在场决定有几个） |
| workspace | 头部（媒体名 + 「收起」）+ 主体：空态大按钮 / 录制中的计时·波形·暂停·停止 |
| saved | 两行面板：`已保存 · M:SS` + 名字输入 + 播放（音频）+「再录一条」+「收起」；第二行是波形（仅音频） |

三种形态占的都是**捕捉区那一行的位置**，列表面板跟着上下移动 —— 不做弹层，也不新开一段主区。

## 3. 状态怎么走

| 动作 | 变成 |
|---|---|
| 点 `Tile` | tiles → workspace（空态，不录） |
| 点大圆钮 | workspace → 录制中（长录） |
| 按住空格 | 任何地方 → workspace（录制中，松手即停） |
| 暂停 / 继续 | 录制中 ⇄ 已暂停 |
| 停止 | 录制中 / 已暂停 → saved（提交成功之后） |
| 松手（对讲式） | 停止并落库，**直接回 tiles**，不进 saved、不命名 |
| 「再录一条」 | saved → workspace（空态） |
| 「收起」 | workspace / saved → tiles |
| 录制中、上传中点「收起」 | 先收起；组件卸载时停止并提交，落库后不再把面板打开 |

录制、上传、设备门禁、暂停、波形都在客户端（引擎）里，插件不重复判断。

## 4. 两种录法

**点一下 = 长录。** 桌面端录音可以很长：上限设成「不限」（`max_seconds = 0`），
录到不想录为止。长录必须能暂停——有人是一句一句录的。

**按住空格 = 对讲。** 按住时立刻进录音工作区并开录，手一松就停、就落库、就回列表。
这适合「说一句就走」。它**不进命名**：对讲式的那句话本来就是速记，多一步就慢了。

- 快捷键只在焦点不在输入框时生效，压着不放只触发一次。
- 误触保护：按下不到 400ms 就松开，不落库。

## 5. 已保存条与命名

- 保存即落库，标题先按**时间轴**起：`语音 11-11 03:41` / `视频 11-11 03:41`（月-日 时:分）。
  同一分钟连录两条会同名 —— 手机录音机也这样，靠时间与时长区分；转写落地后会更好。
- 已保存条第一行是名字输入框，预填默认名：回车即改名，不改就保持默认，收起等于接受默认。
- 改名是改标题，不动媒体、不动创建时间。
- 音频有播放按钮（点的时候才去向 media 取字节）；视频不给内联播放（16:9 塞不进一条窄条），在详情里看。
- 已保存条不是持久状态：收起 / 再录一条 / 换页就没了。

## 6. 波形

- **不自己画，用 [wavesurfer.js](https://wavesurfer.xyz/)**（录音用它的 record 插件）。
  这类东西（滚动窗口、瀑布式采样、暂停、设备选择）是一整块成熟能力，自己拼采样窗口只会拼出
  「越录越窄」那种 bug。
- 录制中是插件自带的**滚动波形**：窗口固定 10 秒，新的从右边进、旧的从左边出，宽度不随录制时长缩水。
- 保存后的静态波形也交给它：节点只给媒体地址（`src`），它自己去取音频、自己解音量。
  所以载荷里不再有峰值，波形也不需要落库 —— 详情页以后想画，给同一个地址就行。

## 7. 时长与上限

| | 上限 | 为什么 |
|---|---|---|
| 音频 | 不限 | 一小时 opus 也就几十 MB，桌面端没必要拦 |
| 视频 | 30 分钟 | 720p 一分钟约 5MB，再长就该提示用户分段了 |

配置在 `[audio] max_seconds` / `[video] max_seconds`；`0` 表示不限。

## 8. 一次都不许丢

- 停止 = 落库。
- 组件卸载（收起、换页、关窗口前的最后一步）也要停止并落库。
- 视频 / 音频上传失败：原地给原因 + 「重试」，字节还在内存里，不进 store。
- 已知限制：收起时视频还在上传，上传失败就没有界面可重试（只写日志）。要做成上传队列是后话。

## 9. 已知问题（v1 接受）

- 同一分钟连录两条同名，只能靠时长与时间区分。
- 详情页还没有波形（已保存条有；节点给地址就能画，只是详情还没放）。
- 头部「收起」紧跟媒体名（左对齐），不做两端对齐：`Row` 没有 spread，为这个加 prop 不值。
- 已保存条的改名只在那一会儿有效；错过了要回详情改（详情还没有改名入口）。
- **收起之后界面上看不到时长**：`record` 里不存时长，默认名又是时间轴，所以「语音 11-11 03:41」
  比原来的「语音 0:12」少了这一段信息。要补就得给 store 加字段，而开发期改字段会
  DROP TABLE 重建（见 [迁移](migrations.md)），会清掉本地数据 —— 发布前再一起做。

## 10. 文字这一页

文字仍是最小形态：就地一行 `input`，回车落库，存完收起。

它真正要回答的问题不是版式，是**「什么时候算一条」**：回车、失焦、停手两秒、还是显式完成。
这个问题定了再单独设计（编辑器、草稿、转成需求 / 项目都从这里分叉）。

## 11. 边界

- 节点就这些：`Panel` / `Row` / `Text` / `Button` / `Audio` / `Input`，加两个新节点
  `Hotkey`（不可见，按下/松开）和 `Waveform`（静态柱状）。SDK 与协议在 [协议设计](protocol.md) 里。
- 一屏仍然只有一个实心 accent（首页是搜索按钮）。工作区里的主操作是描边药丸。
- 三种媒体共用同一块版式，只换主体那个节点。

## 12. 怎么验证

- `uv run python scripts/check.py` 全绿。
- 人工：点「录音」→ 不自动开录 → 点圆钮录 2 秒 → 暂停 → 继续 → 停止 → 出「已保存 · 0:02」+ 波形 + 默认名 → 改个名回车 → 收起 → feed 顶部是新名字。
- 人工：在首页按住空格说一句，松手 → 直接回首页，feed 顶部多一条。
- 人工：录到一半点「收起」→ 条目仍然落库。
