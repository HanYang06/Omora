# 架构总览

> 状态：草稿 · 对应 ADR-0001 / ADR-0002

## 一句话

Omora 由两个很小的核心和一个很大的插件面组成：Python 内核负责一切逻辑与状态，TypeScript 渲染器负责一切界面；两者之间只有协议，没有共享内存。

## 设计原则

1. **一切皆插件，核心只保留引导、信任、契约。**
2. **UI 是数据，不是代码。** 插件给出节点树，渲染器负责画。
3. **内核是唯一真相源。** UI 只持有投影。
4. **协议是产品。** 能接多少种语言由协议决定，与内核语言无关。
5. **官方无后门。** 官方功能与第三方插件走同一扇门。

## 三条契约

| 契约 | 双方 | 兼容承诺 | 优化目标 |
|---|---|---|---|
| C1 | 内核 ↔ 前端 | 无，可随时破坏 | 延迟、批处理、背压 |
| C2 | 宿主 ↔ 插件 | 语义化版本 | 最小、语言中立、权限 |
| C3 | 插件 ↔ 渲染器 | 版本化 + 能力探测 | 表达力与稳定性平衡 |

详见 [contracts.md](contracts.md)。

## 数据流

铁律：

> **命令上行 · 事件下行 · UI 是投影 · 无共享状态**

1. 用户操作 → UI 发 C1 命令 → 内核校验、落库、产生事件。
2. 内核把事件推给所有订阅者（前端、插件）。
3. 前端把事件合并进投影，渲染器增量更新。
4. 插件通过 C2 收到事件，可以调用能力、贡献 UI。

UI 的乐观更新只允许出现在前端，冲突以内核事件为准。

## 部署形态

| 形态 | 组成 | 状态 |
|---|---|---|
| 本地开发 | Python WS + Vite dev server | P0 |
| 本地 App | Electron / Tauri 壳 + Python sidecar + WebView | 后置 |
| 服务器 | 同一 Python 内核 + 浏览器 | 后置 |
| 移动 | 瘦客户端，吃 C1 + C3 的子集 | 后置 |

## 信任分层

| 层级 | 承载 | 隔离强度 | 默认用于 |
|---|---|---|---|
| L0 | 内核进程内，同语言，scope | 可见性隔离 | 官方插件 |
| L1 | Worker / isolate | 可终止 | 大量第三方同语言插件 |
| L2 | 共享宿主进程池 | 进程级 | 异语言批次 |
| L3 | 独占进程 | 完全隔离 | 高风险或重型插件 |
| L4 | WASM 实例池 | 沙箱 + 资源上限 | 不可信、多语言 |
| L5 | 远程插件 | 网络边界 | 服务器、团队共享 |

协议在 L0–L5 完全一致，因此插件可以在层级间晋升而不改代码。

## 技术栈

| 位置 | 选择 | 备注 |
|---|---|---|
| 内核 | Python 3.12+，uv，asyncio | 不引 Web 框架；P0 只用 WebSocket |
| 存储 | SQLite + 追加事件日志 | 迁移与备份是核心能力 |
| 契约 | JSON-RPC 2.0 + JSON Schema | 语言中立 |
| 前端 | TypeScript strict + Vite | 渲染框架暂定 React，被渲染器隔离 |
| 执行单元 | Python 多进程 / WASM（后续） | P0 只用同进程插件 |
