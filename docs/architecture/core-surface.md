# 核心边界

> 状态：草稿 · 对应 ADR-0002

## 1. 判定标准：三道测试

| 测试 | 问题 | 通过即核心 |
|---|---|---|
| 引导性 | 插件加载之前，它是否必须已经存在？ | bootstrap、配置、工作区、装配 |
| 信任性 | 交给插件自己去执行，是否等于没有执行？ | 权限、沙箱、能力代理、审计 |
| 契约性 | 它本身是否就是大家共享的那份契约？ | 传输、schema、版本协商 |

**规则：三条满足至少一条 → 核心；三条都不满足 → 一律插件。**

以后新增任何核心能力，先过这三条，再谈实现。

## 2. 核心面：七个子系统

| 子系统 | 提供 | 绝不提供 |
|---|---|---|
| 启动与装配 | bootstrap、配置、工作区、服务容器（provide / inject / lifecycle / scope）、插件宿主（发现 / 安装 / 版本 / 热重载 / 隔离） | 任何具体功能 |
| 执行单元 | 进程 / 线程 / WASM 池、资源计量、崩溃隔离与重启、任务队列 | 业务并发策略 |
| 信任 | 能力模型与授权、能力代理、沙箱执行、身份与密钥、包签名与信任等级、审计 | 具体策略内容（可配置） |
| 契约 | 传输、RPC（流 / 取消 / 背压）、schema 注册与校验、版本协商、错误模型 | 任何业务方法 |
| 状态 | 事务存储原语、迁移、备份、追加事件日志、Blob 存储、工作区 | 具体表与实体 |
| 界面运行时 | 渲染器、布局、槽位、主题 token、原语控件、交互原语、控件注册表、沙箱 UI 宿主、命令 / 快捷键 / 弹窗 / 通知 | 具体视图与业务界面 |
| 运维 | 日志 / 指标 / 追踪（按插件归因）、诊断、任务管理、更新 | 仪表盘 |

## 3. 原语与服务：两个不同的东西

**原语（Primitive）** 由核心提供，插件申请使用；**服务（Service）** 由插件提供并注册，其他插件消费。核心只维护注册表与路由，不实现服务。

| 原语 | 归属 | 说明 |
|---|---|---|
| store.tx | 核心 | 事务、迁移、备份 |
| log.append | 核心 | 追加事件、分配 revision |
| provide / inject / resolve | 核心 | 服务注册与依赖解析 |
| grant / check / audit | 核心 | 能力授权与审计 |
| spawn / kill / limit | 核心 | 执行单元与资源上限 |
| jobs.submit | 核心 | 长任务与取消 |
| commands.register / dispatch | 核心 | 命令机制 |
| slots.register / widgets.register | 核心 | UI 扩展点 |
| clock / id / random | 核心 | 可注入，便于测试 |
| log / metric | 核心 | 自动按插件归因 |

| 服务 | 提供方 | 说明 |
|---|---|---|
| git | 官方插件 | GitHub / GitLab 适配，核心零 provider 代码 |
| ai | 官方插件 | LLM 调用与提示管理 |
| search | 官方插件 | 召回与排序，索引原语在核心 |

## 4. 槽位分类

| 槽位 | 用途 | P0 |
|---|---|---|
| sidebar | 导航与列表 | 是 |
| main | 主工作区 | 是 |
| panel | 辅助面板 | 否 |
| detail | 详情区 | 否 |
| statusbar | 状态与进度 | 否 |
| commandPalette | 命令入口 | 否 |
| settings | 设置项 | 否 |
| onboarding | 引导 | 否 |
| modal | 模态层 | 否 |

槽位是「插件能改 UI」的机制底座：插件不改布局，只往已有槽位里填内容。

## 5. 反腐蚀清单

以下内容出现在核心，一律视为设计错误：

- 领域模型：Idea / Project / Requirement / Task
- 具体界面：收件箱、看板、时间线、关系图、日历
- 任何一家的适配器：GitHub、GitLab、S3、OSS、NAS、WebDAV
- AI 与 LLM 逻辑、提示词、向量检索
- 导入导出格式
- 主题内容、图标内容、快捷键内容
- 搜索界面、召回与排序策略
- 同步算法、冲突解决策略
- 活动流、通知内容

**一句话：核心零领域词汇。** 核心里出现 `Idea` 或 `Kanban`，就是边界破了。

## 6. 官方插件清单（自证用）

| 插件 | 它证明什么 |
|---|---|
| ideas | 捕获、整理、检索的完整闭环 |

| ai-assistant | 长任务、密钥、能力申请 |
| search-ui | 检索体验可替换 |

这份清单是**验收工具**：任何一个写不顺，都是核心 API 缺能力，不是那个功能的问题。

## 7. 争议裁定

| 争议点 | 裁定 |
|---|---|
| UI 渲染 vs 基础组件 | 渲染器 + 原语控件 + 槽位 = 核心；复合控件与设计系统 = 官方插件，注册进控件表 |
| 存储 | SQLite 事务原语 + 事件日志 = 核心；存到 NAS / OSS / 服务器 = 插件，实现的是复制目标 |
| Git | 核心只提供服务注册与能力路由；`git` 服务由官方插件提供 |
| 搜索 | FTS 原语核心；搜索界面与排序策略插件 |
| 线程管理 | 不对插件承诺线程并行；只暴露执行单元抽象：I/O 线程池 / CPU 进程池 / WASM 实例 |
| 插件市场 | 不做官方市场；包格式、签名校验、信任等级是核心 |
| 主题 / 命令 | 机制核心，内容插件 |
| 壳 | 窗口、布局、槽位核心；视图插件 |

## 8. 准入流程

1. 写一页纸：要加什么、为什么、过哪条测试；
2. 若三条都不满足，改为插件，并把缺口补进 C2 / C3；
3. 通过后记入 ADR 附录；
4. 每季度反向扫描：把能下放的核心能力下放；
5. 官方功能必须用公开 API 实现，禁止后门。
