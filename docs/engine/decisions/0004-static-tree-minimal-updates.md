# ADR-0004：静态结构与最小节点更新是目标架构

- **状态**：已接受（2026-11-18）
- **决策者**：项目作者 + Lead
- **相关**：[ADR-0003](0003-v1-tree-is-a-spike.md)（被取代）、[路线图](../../roadmap.md)、[V1 树](../../planning/v1-tree.md)

## 背景

旧结构有两个同源缺陷：

1. **每事件全树重建**：事件 → 整份 view 序列化 → 整帧传输 → 全树链接 → 全树替换 → 按 id diff。每一层 O(N)。项目自己的文档（`docs/design/packages.md` §7.3）写着“每个事件交整份 view（重链 + 全量替换）”。
2. **运行时组织树**：启动与切页也整棵链接；静态构建只覆盖空态骨架（`scripts/static_ui.py`），真实视图仍运行时组织。

两个缺陷同源：**结构在运行时才成立**。树小看不出来，树大必然出现；这是构造决定的，不需要等测试证明。

V1 树（`dendro.tree/1`）已经把节点契约、构建期 compose、runtime mount、Page / State / When / Bind、Node scope 落地。它解决的是同一个问题：节点可单独寻址、可单独替换，结构在构建期成立，运行时只做数据与状态绑定。

同一天里，V1 被写过三种定位：接管 → 扫雷 → 目标架构。代码没变，变的是对“它解决什么”的认识；没有 ADR 时，同一件事会被反复重新定性。ADR-0003 的“扫雷、到期归档”是第二次误判，本 ADR 取代它。

## 决定

1. **静态结构与最小节点更新是引擎的一等约束**，不是性能优化项。
2. **V1 是目标架构**，分阶段接管默认入口；Slot 逐步退场。
3. **先做核心**：静态结构、最小节点更新、ops 协议、页面插件迁移、旧路径删除、复杂度护栏。
4. **非核心随业务维护**：组件词表、`reactions`、远程来源、订阅 / 媒体登记、集合嵌套、权限细项，不单独排期。
5. **引擎先完善，产品闭环随后**：长期做 Idea 闭环 + Project 闭环；需求（requirements）后置。
6. **ADR-0003 被本 ADR 取代**。

## 后果

**得到**：

- 单一目标架构，不再有“两个下一步”。
- 每次事件的代价与变更节点相关，不随全树增长。
- 产品迁移有明确路径：一页一页迁，旧路径留作回滚。

**要自己负责**：

- ops 协议语义：原子性、版本、全量兜底、跨语言一致。
- 迁移期间的兼容与回滚；旧路径删早了没有退路。
- 复杂度护栏：不测绝对值，测斜率。

**风险与缓解**：

- 风险：ops 设计错误导致丢更新。缓解：base 版本 + 原子回滚 + 跨语言 fixture。
- 风险：迁移拖延。缓解：每个阶段有退出条件与止损；单个插件迁不动不阻塞整体。

## 被否掉的方案

- **继续全量 view + 局部优化**：DOM 复用只省创建，不省序列化、传输、链接、替换、diff。
- **直接切默认入口**：协议未定，丢更新风险；没有回滚路径。
- **把 V1 当扫雷到期归档**（ADR-0003）：缺陷仍在，业务迁移成本更高。

## 验收

- 一个真实页面走新路径，事件不再整树重建。
- 复杂度斜率 O(k)：事件 → DOM 不随总节点数增长。
- 页面插件迁完，旧 Slot 默认路径删除，全量门禁绿。
