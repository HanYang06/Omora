# ADR-0003：V1 树是扫雷轨道，不接管默认入口

- **状态**：**被取代**（2026-11-18，[ADR-0004](0004-static-tree-minimal-updates.md)）
- **决策者**：项目作者 + Lead
- **相关**：[路线图](../../roadmap.md)、[V1 树](../../planning/v1-tree.md)、[README](../README.md)

> 本文保留历史：V1 曾被定位为“扫雷、不接管、到期归档”。ADR-0004 已改为“目标架构、分阶段接管”；本文的定位不再有效。

## 背景

2026-11-18 一天内落了 5 个 PR（#114–#118），把 `dendro.tree/1` 的契约、node scope、Page/State/When/Bind、构建期 composer、runtime mount 作为独立模块落了。同一时间，`docs/roadmap.md` 把它写成"V1 接管主会话，然后退役旧 Slot"。

但事实是：

- V1 的 6,518 行只被自己的测试 import，没有一行产品代码引用它；
- 默认入口仍是 Slot，S0–S6 与 S7.1 都已落在 Slot 上；
- 两套树没有转换器，身份模型（`id/addr` vs `chain`）和状态哲学（整份 view vs 可变 state）都不同；
- `docs/engine/README.md` 写的下一步是 S7，与 roadmap 相反。

这不是"做得对不对"的问题，是**没有写清 V1 是什么**。

## 决定

1. V1 定位为**扫雷轨道**：提前踩旧引擎没解决的问题，产出结论，不接管默认入口。
2. 结论出来前：不接 app、不加 `?engine=v1`、不扩 kind、不写 V1 → Slot 转换器。
3. 到期日 **2026-12-02**；到期必须有一个动作：吸收某个机制、归档代码、或按对比证据另写迁移 ADR。
4. 路线图不再写"V1 接管"；V1 的四个缺口记入地基候选，每条带触发条件。

## 后果

**得到**：

- 默认入口唯一，不再有"两个下一步"。
- V1 踩出来的四个缺口（页面状态、节点生命周期、构建期组合、第二运行时）被记录，不会随代码一起丢。
- 地基投入被产品项约束，不再无限扩张。

**要自己负责**：

- V1 代码留在 `main` 期间的心智成本与 CI 时间，到期必须处理。
- 12-02 要做一个收口决定，不能拖。

**风险与缓解**：

- 风险：Slot 的 state/when 补不动，产品页面复杂度上来后撞同一堵墙。缓解：缺口表里有触发条件，出现就解冻 V1 的对应机制。
- 风险：扫雷结论被当成"V1 永远不做"。缓解：本文只定"现在不换树"，不定"永远不换"。

## 被否掉的方案

- **立即接管**：双契约、状态哲学冲突、构建期组合表达不了运行后来源；成本在现阶段无法回收。
- **立即删除**：四个缺口刚被踩出来，实现还有参考价值；删了就要重踩。
- **无限期冻结**：隔离代码没有到期日会腐烂，最终变成没人敢碰的第二主线。

## 验收

- README / ARCHITECTURE / roadmap / engine README / TODO 对 V1 的口径一致。
- 2026-12-02 有一个 ADR、一次归档或一份迁移提议落地。
